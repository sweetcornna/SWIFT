# 低空闪翼：面向城市配送的无人机三维避障系统项目计划书

版本：v0.1  
日期：2026-06-02  
项目仓库：`sweetcornna/SWIFT`  
本地仿真底座：`D:\project\pybullet`

## 一、项目概述

“低空闪翼”面向城市低空配送场景，建设一套基于 PyBullet 的无人机三维智能避障仿真与验证系统。项目以 PPO 作为连续动作决策底座，以 HCA 分层交叉注意力作为多源感知核心，以 APF 人工势场向量作为安全先验，形成“感知-决策-安全”一体化的混合智能架构。

项目目标不是只做一个演示动画，而是形成可测试、可复现、可扩展的工程体系：既能支撑大学生创新训练项目立项、过程检查和结题答辩，也能为后续强化学习训练、消融实验、软件著作权材料和演示视频提供统一证据链。

## 二、立项背景与问题定义

城市低空配送正在从试点演示走向规模化运营。与开阔区域单机飞行不同，城市末端配送同时面对高建筑密度、多机同域运行、动态障碍频发、配送时效约束和安全责任边界等问题。传统路径规划方法在静态环境中具有可解释性，但在高动态、强耦合的三维城市空域中容易出现局部最优、实时性不足和多目标协调困难。

本项目聚焦的核心问题包括：

- 安全问题：无人机需要在建筑、动态无人机和低空障碍物之间保持足够安全距离。
- 效率问题：配送任务不仅要求到达目标，还要求路径平滑、时间可控、能耗合理。
- 感知问题：目标点、雷达测距、障碍物、APF 向量和机间相对状态属于异构信息，不能简单拼接后交给网络“自行猜测”优先级。
- 工程问题：算法成果必须能在统一仓库、统一配置、统一测试和统一实验记录下复现。

## 三、建设目标

项目建设分为研究目标、工程目标和交付目标三类。

### 3.1 研究目标

1. 建立面向城市低空配送的三维连续动作空间 MDP 建模方案。
2. 实现 PPO+MLP 基础避障策略，形成可演示的保底模型。
3. 将 HCA 从多机协同场景迁移到单机多源感知场景，构建目标感知层和威胁感知层。
4. 将 APF 吸引力和斥力向量嵌入 HCA 感知流程，验证其对收敛速度、安全性和可解释性的贡献。
5. 通过 MLP、HCA、HCA+APF 三组消融实验验证模块价值。

### 3.2 工程目标

1. 将 `D:\project\SWIFT` 建设为企业级主项目仓库。
2. 将 `D:\project\pybullet` 作为外部本地仿真底座，通过 adapter 接入，不直接复制或混写。
3. 建立配置、测试、健康检查、指标、实验记录和文档体系。
4. 保证每个阶段都有可运行、可验证、可回退的成果。

### 3.3 交付目标

- 基于 PyBullet 的无人机智能避障三维仿真系统 1 套。
- 项目研究报告和结题报告各 1 份。
- 可演示 Demo 视频 1 份，覆盖静态建筑、动态多机威胁和高度层切换场景。
- 消融实验数据与训练曲线若干。
- 软件著作权申请材料 1 套，视最终成果质量提交。

## 四、总体技术路线

项目采用“理论分析 -> 算法设计 -> 仿真验证 -> 消融对比 -> 成果整理”的路线推进。

| 层级 | 输入 | 方法 | 输出 | 项目作用 |
| --- | --- | --- | --- | --- |
| 环境感知层 | 自身位姿、速度、目标相对位置、雷达测距、动态无人机状态 | 多源状态编码 | 局部观测空间 | 为策略决策提供统一输入 |
| APF 先验层 | 目标点、建筑障碍、动态威胁 | 人工势场法 | 吸引力/斥力向量 | 提供物理可解释安全先验 |
| HCA 注意力层 | 自身状态、目标信息、障碍信息、APF 向量 | 两层分层交叉注意力 | 目标优先级与威胁优先级特征 | 实现多源信息解耦 |
| PPO 决策层 | HCA 或 MLP 输出特征 | PPO Actor-Critic | 三维连续动作指令 | 输出速度、航向和爬升控制 |
| 仿真验证层 | 飞行轨迹、碰撞信息、到达状态 | PyBullet 三维仿真与指标统计 | 成功率、路径平滑度、安全距离等 | 支撑训练、对比和演示 |

## 五、系统架构与仓库边界

SWIFT 主仓负责项目治理、配置、领域模型、训练与评估入口、实验记录和文档。`D:\project\pybullet` 保持为外部仿真底座，由 SWIFT 通过命令级 adapter 验证和调用。

### 5.1 主仓职责

- `configs/`：项目、仿真、训练、评估配置。
- `src/swift/config/`：配置加载与校验。
- `src/swift/core/`：无人机状态、动作、奖励、指标等领域模型。
- `src/swift/sim/`：PyBullet substrate adapter。
- `src/swift/envs/`：未来 Gymnasium 风格环境接口。
- `src/swift/rl/`：PPO、HCA、APF 配置和后续算法实现边界。
- `src/swift/experiments/`：实验矩阵、指标命名和结果结构。
- `docs/`：项目章程、架构、路线图、风险登记、源材料记录和计划书。

### 5.2 PyBullet 接入原则

第一阶段采用命令级接入，而不是直接 import `D:\project\pybullet` 内部脚本。这样可以降低耦合，避免把仍处于实验状态的底座代码直接变成主仓依赖。当前 adapter 需要验证：

- `D:\project\pybullet` 存在。
- `pixi.toml` 存在且能解析。
- `.tools\pixi\pixi.exe` 存在。
- `test` 和 `drone-demo` 任务存在。
- check-only 与 live smoke 命令能够输出明确状态。

## 六、核心研究内容

### 6.1 PPO+MLP 基线模型

第一阶段实现 PPO+MLP 基础避障策略。该模型作为保底成果，优先保证能够在简化城市低空环境中完成起飞、导航、避障、悬停和降落等基本任务。基线模型用于后续 HCA 和 APF 融合效果的对照。

### 6.2 HCA 分层感知升级

HCA 改造为两层注意力结构：

1. 目标感知层：以自身状态作为 Query，以目标信息和 APF 吸引力作为 Key/Value，回答“我要去哪”。
2. 威胁感知层：以目标感知层输出作为增强 Query，以静态障碍、动态机间威胁和 APF 斥力作为 Key/Value，回答“路上有什么风险”。

该设计将多机协同中的分层注意力思想迁移到单机城市配送避障任务中，使策略网络具备更清晰的信息优先级结构。

### 6.3 APF 深度融合

APF 不作为外部路径规划器或独立安全过滤器，而是以吸引力/斥力向量形式进入 HCA 感知流程。这样既保留 APF 的物理解释性，又允许 PPO 策略在复杂场景中学习何时采纳或修正 APF 建议。

### 6.4 三维仿真与消融实验

基于 PyBullet 构建城市低空三维环境：

- 随机高度建筑群。
- 动态虚拟无人机 2-3 架。
- 随机配送目标点。
- 雷达测距与碰撞检测。
- 多建筑密度、多动态障碍数量、多目标点组合测试。

消融实验至少包含：

| 实验组 | 算法组合 | 验证目的 |
| --- | --- | --- |
| Baseline | PPO+MLP | 建立可运行保底基线 |
| HCA-only | PPO+HCA | 验证分层感知价值 |
| Full | PPO+HCA+APF | 验证 APF 深度融合贡献 |

## 八、实验与评价体系

项目评价不只看“是否到达”，而是采用综合指标。

| 指标 | 含义 | 数据来源 | 用途 |
| --- | --- | --- | --- |
| 成功率 | 在限定步数内安全到达目标的比例 | episode 结果 | 衡量任务完成能力 |
| 碰撞率 | 与建筑或动态无人机发生碰撞的比例 | PyBullet 碰撞检测 | 衡量安全性 |
| 平均路径长度 | 完成任务的轨迹长度 | 飞行轨迹点 | 衡量路径经济性 |
| 路径平滑度 | 轨迹转向累计变化 | 轨迹点序列 | 衡量飞行稳定性 |
| 收敛轮数 | 达到稳定成功率所需训练轮数 | 训练日志 | 衡量训练效率 |
| 最小机间安全距离 | 与动态无人机最近距离 | 多机状态记录 | 衡量同域适配能力 |

每个实验组需要记录统一随机种子、环境配置、训练参数、模型版本和评估结果。实验输出统一放入 `outputs/`，并默认不纳入 Git 跟踪。

## 十一、企业级实施标准

项目实施遵循以下标准：

1. 配置优先：路径、训练参数、评估指标和输出目录通过配置管理。
2. 测试先行：新增功能必须有对应测试或可复现实验脚本。
3. 阶段交付：每个阶段必须有可运行产物，不依赖最后一次“大集成”。
4. 指标闭环：所有 Demo 结论必须能追溯到日志、指标或实验记录。
5. 边界清晰：SWIFT 主仓负责治理与编排，PyBullet 底座负责仿真执行。
6. 输出隔离：训练日志、模型权重、视频素材默认放入 `outputs/`，避免污染代码仓。
7. 可解释性优先：APF 向量、注意力权重和奖励项需要尽量能被记录和分析。

## 十二、风险与控制措施

| 风险 | 影响 | 控制措施 |
| --- | --- | --- |
| 稀疏奖励导致训练困难 | 模型长期无法学会到达目标 | 引入距离逼近、避障、安全距离、时效性等 shaped reward |
| PPO-HCA 耦合不稳定 | 注意力层导致训练发散 | 使用归一化、维度对齐、梯度裁剪和 MLP 基线对照 |
| APF 局部最优 | 在 U 型障碍等场景出现错误引导 | 保留 HCA-only 消融组，让 RL 学会修正 APF |
| GPU 资源不足 | 大规模训练进度受阻 | 保留 CPU smoke、小场景训练和云端 GPU 预案 |
| PyBullet 底座漂移 | 主仓 adapter 与底座任务不一致 | 使用健康检查和任务级验证，记录 adapter 假设 |
| Demo 不可复现 | 答辩展示和实验证据脱节 | 以 headless 测试、日志和指标为准，视频只作为展示材料 |
